# 明中都微信小游戏构建与上传说明

本项目发布的是 **微信小游戏**，不是普通业务型微信小程序。Cocos Creator 负责生成小游戏工程，微信开发者工具负责真机预览、上传和版本管理。

## 当前工程结构

- 横屏运行，设计分辨率为 1280 × 720。
- `Start.scene` 是首场景。
- `start-scene` 和引擎运行所需文件进入微信主包。
- `main`、`resources` 是远程 Asset Bundle，从腾讯云 HTTPS 地址按需下载。
- Cocos 引擎代码随小游戏主包发布，不依赖需要账号单独授权的微信引擎插件。
- Cocos 服务器基址为 `https://nyasd.net/mingzhongdu-wechat/`，实际远程资源目录为 `https://nyasd.net/mingzhongdu-wechat/remote/`。
- 问卷接口使用 `https://nyasd.net/api/mingzhongdu/feedback`。
- AI 生图角色功能已经移除，不需要申请相机、相册或 AI 服务权限。

## 生成可导入的雏形工程

先在 Cocos Creator 中重新构建微信小游戏，输出目录保持为 `build/wechatgame/`。然后在项目根目录依次运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/prepare-wechat-release.ps1
powershell -ExecutionPolicy Bypass -File tools/finalize-wechat-project.ps1
```

不要直接复用 `tmp/` 下的验证构建；它可能仍然包含旧代码。只有明确做回归测试时，才通过 `-BuildRoot` 显式指定验证构建。

脚本会生成：

- `dist/wechatgame-upload/`：导入微信开发者工具的小游戏工程。
- `dist/wechatgame-remote/`：部署到服务器的远程资源。
- `dist/mingzhongdu-wechat-project.zip`：小游戏工程压缩包。
- `dist/mingzhongdu-wechat-remote.zip`：远程资源压缩包。
- `dist/wechat-release-manifest.json`：包体大小、地址和 SHA-256 校验值。

此模式保留 Cocos 测试 AppID，只用于开发者工具导入、界面展示和本地调试，不能代表正式上传资格。

## 备案和正式 AppID 就绪后的生成命令

把命令中的 AppID 换成团队的真实小游戏 AppID：

```powershell
powershell -ExecutionPolicy Bypass -File tools/finalize-wechat-project.ps1 `
  -AppId wx1234567890abcdef `
  -ForUpload
```

`-ForUpload` 会拒绝测试 AppID，并检查横屏配置、远程包、资源地址、服务器远程版本和主包大小。应先把 `dist/wechatgame-remote/` 上传到服务器，再运行这条命令做最终校验。通过后，`dist/wechatgame-upload/` 就是微信开发者工具的正式导入目录。

## 微信公众平台后台需要配置的域名

域名只填写协议和域名，不填写 `/mingzhongdu-wechat/remote/` 等路径，也不填写端口：

- `downloadFile 合法域名`：`https://nyasd.net`
- `request 合法域名`：`https://nyasd.net`

其中远程图片、场景和角色资源使用 `downloadFile`；问卷提交使用 `request`。开发者工具可以临时关闭合法域名校验用于本地排错，但正式预览、真机和上传前必须在平台后台配置。

## 导入微信开发者工具

1. 安装微信开发者工具并登录有该小游戏权限的微信账号。
2. 选择“导入项目”。
3. 项目目录选择 `dist/wechatgame-upload/`。
4. 项目类型确认是“小游戏”，不是“小程序”。
5. 填入团队真实 AppID；正式上传前应使用上面的 `-ForUpload` 命令重新生成一次。
6. 首次运行确认启动页、角色动画、地图切换、放大镜碎片、知识交互和设置问卷均正常。
7. 使用真机调试测试 Android 和 iOS，重点观察首屏耗时、远程资源下载失败提示和弱网重试。
8. 在开发者工具中点击“上传”，填写版本号和说明；之后在微信公众平台提交体验版或审核。

## 服务器资源更新

每次 Cocos 重新构建后都必须同时更新 `dist/wechatgame-remote/`，否则小游戏代码与服务器资源版本号可能不匹配。服务器目标目录对应：

```text
https://nyasd.net/mingzhongdu-wechat/remote/
```

服务器更新必须采用“合并新增文件”的方式，不能先清空或直接替换整个 `remote/` 目录。Cocos 文件名包含版本哈希，旧体验版仍会请求旧哈希文件；删除旧文件会导致已经发给体验成员的版本长期卡在 Cocos 启动画面。

推荐发布顺序：

1. 将 `dist/wechatgame-remote/` 合并到服务器现有 `remote/` 目录，并至少保留当前版和上一版的哈希文件。
2. 验证新旧版本的 `main/config.*.json`、`resources/config.*.json` 均可通过 HTTPS 下载。
3. 再在微信开发者工具上传新的小游戏代码，并切换体验版。
4. 确认所有体验成员已升级后，才清理不再引用的老资源。

## 验收清单

- 主包小于 4 MiB，并至少保留约 0.5 MiB 的余量。
- `game.json` 为横屏。
- `project.config.json` 为正式 AppID 且 `compileType` 为 `game`。
- `main`、`resources` 两个远程包都存在。
- `https://nyasd.net` 已加入 `downloadFile` 与 `request` 合法域名。
- 服务器 HTTPS 证书正常，远程目录可访问。
- 清理缓存后首次启动通过，第二次启动缓存命中。
- 真机完成一轮：开始游戏 → 地图切换 → 地点交互 → 放大镜拾取 → 游客中心拼图 → 成就。
