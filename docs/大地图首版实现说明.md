# 明中都大地图首版实现说明

> 实现日期：2026-07-21  
> Cocos Creator：3.8.8  
> 目标平台：微信小游戏（横屏）  
> 当前状态：大地图可运行模板

## 1. 当前交互基线

玩家不是点击地点进行传送，而是在俯瞰大地图上直接移动：

```text
虚拟摇杆 / WASD / 方向键
        ↓
玩家在大地图连续移动
        ↓
相机平滑跟随并限制在地图边缘
        ↓
进入地点彩色触发圆环
        ↓
自动打开地点场景（目前为占位层）
        ↓
返回大地图并从触发区外继续移动
```

大地图承担压缩现实距离的作用，但操作方式仍是“行走”，从而保留探索感。当前不加入点击节点、自动寻路、路线动画或快速传送按钮。

## 2. 已实现内容

- 使用审批通过的卫星图转绘作为大地图底图。
- 横屏自适应的地图显示。
- 左下角虚拟摇杆，支持手机触摸。
- 支持电脑端 `WASD` 和方向键调试。
- 玩家连续移动。
- 相机平滑跟随与地图边缘限制。
- 五个可配置地点入口：`1`、`2`、`2.5`、`3`、`4`。
- 进入地点触发范围后自动打开地点占位层。
- 从占位层返回时将玩家推出触发范围，避免反复自动进入。
- 自定义圆形玩家与矩形障碍碰撞，不启用 Cocos 物理引擎。

## 3. 工程结构

```text
assets/
├─ resources/
│  └─ map/
│     └─ overworld.png
├─ scenes/
│  └─ Overworld.scene
└─ scripts/
   └─ overworld/
      ├─ OverworldBootstrap.ts
      └─ OverworldConfig.ts
```

### `Overworld.scene`

场景保留 Canvas、Camera、启动组件，以及一套编辑器校准节点 `MapCalibration`。运行时仍由启动组件创建正式地图、玩家、HUD、摇杆和地点占位层；校准节点只负责让底图、入口和出生点在编辑器里可见、可拖动。

### `OverworldBootstrap.ts`

负责：

- 创建运行时节点；
- 加载大地图；
- 接收摇杆和键盘输入；
- 玩家移动；
- 自定义碰撞；
- 相机跟随；
- 入口触发；
- 屏幕 UI 适配。

### `OverworldConfig.ts`

负责地图模板的可变数据：

- 地图尺寸；
- 玩家出生点；
- 障碍矩形；
- 入口编号、名称、位置、半径和颜色。

后续制作另一张大地图时，优先只替换图片并修改该配置，不改核心移动代码。

## 4. 坐标约定

`OverworldConfig.ts` 中的入口默认值使用归一化坐标：

- 左上角：`(0, 0)`；
- 右下角：`(1, 1)`；
- 中心：`(0.5, 0.5)`。

它们用于首次生成校准节点，以及校准节点不存在时的运行兜底。配置示例：

```ts
{
  id: 'location-3',
  title: '地点 3 · 南门',
  normalizedPosition: new Vec2(0.57, 0.77),
  triggerRadius: 72,
  accent: '#9b6754',
}
```

## 5. 障碍配置

首版暂不添加未经确认的水系和建筑碰撞，避免错误阻断路线。地图边缘已经不可越界。确认实际可行走路线后，在 `OVERWORLD_OBSTACLES` 中增加矩形：

```ts
new Rect(x, y, width, height)
```

坐标原点位于地图中心，`x` 向右、`y` 向上。碰撞算法采用“圆形玩家对矩形障碍”，并把横向、纵向移动分开判断，因此角色碰墙后仍可沿墙滑动。

不使用 Box2D，也不创建刚体、重力、力或关节。当前玩法只需要确定性的行走阻挡，自定义碰撞更轻量，也更适合微信小游戏。

## 5.1 可通行道路

2026-07-22 起，大地图不再允许角色在整张图片上任意穿行。路线采用“拐点/交叉点 + 连线”的图结构：

- `OVERWORLD_ROUTE_POINTS`：15 个拐点或交叉点；
- `OVERWORLD_ROUTE_EDGES`：17 条点之间的连接边；
- `MapCalibration/RoutePoints`：Creator 中可调整的对应节点。

角色中心只能处于这些连接边形成的胶囊形走廊内。

每条连接边包含：

```ts
{
  id: 'west-main-a',
  from: 'west-start',
  to: 'west-junction',
  halfWidth: 24,
}
```

仍然使用自定义几何判定，不启用 Cocos 物理引擎。道路半宽进一步收窄到 8–9，出生点若不在道路内，运行时会自动吸附到最近道路。

近似水平、近似竖直的路线已按最小位移原则对齐：同一排节点共享 Y，同一列节点共享 X，使近似直线成为直线、近似直角成为直角；原本明确的斜向连接仍然保留。

拖动 `MapCalibration/RoutePoints/RoutePoint-*` 后，编辑模式会检测点位变化并自动重新连接路线、重算地点交点；不再需要删除或重建整张地图。`MapBackground` 的 SpriteFrame 使用稳定序列化引用，路线刷新不会再异步覆盖底图素材。

西侧旧终点 `west-end` 已删除，`west-junction` 现在直接连接 `diagonal-mid`。编辑器会自动清理已经从配置移除的旧路线节点，重启后不会再次生成。

## 5.2 道路与地点入口点

地点圆本身不再直接触发进入。系统计算“道路中心线与地点圆”的交点，并在每个交点建立半径约 10–16 的独立入口碰撞点。

当前自动生成结果：

| 地点 | 入口点数量 |
|---|---:|
| 游客中心 | 2 |
| 西门 | 2 |
| 石墩 | 3 |
| 古井 | 2 |
| 午门 | 1 |

每个入口都有稳定的方向与图片键，例如：

```text
locations/location-1/west-01
locations/location-1/east-01
locations/location-2/east-01
locations/location-2/northeast-01
```

石墩地点原有的 `east-02` 与 `north-01` 合并为一个东北入口 `northeast-01`；碰撞位置取两个原交点的中点，其余入口保持不变。

入口检测同时检查角色当前点与本帧实际移动线段；即使一帧跨过较小的入口圆，也会触发进入，避免道路收窄后偶尔漏碰入口点。

因此同一地点从不同道路进入时，可以根据 `imageKey` 加载不同视角图片。当前测试阶段碰到入口不会弹窗：

- 两个出口的地点从另一个出口出来；
- 三个出口的地点从其余出口中随机选择；
- 只有一个出口时沿该道路向地点外推出；
- 最终位置再次吸附到道路，并设置短暂冷却，避免立即重复触发。

脚本会发送 `overworld-location-traverse` 事件，其中包含进入与离开的 `entryId / imageKey`，后续地点图片场景直接监听该事件即可。

## 6. 地点切换接口

当前地点内部场景尚未制作，因此自动进入后显示占位层。正式地点场景完成后，将 `openEntryPanel()` 替换为统一的场景切换服务，例如：

```ts
SceneTransition.enter(entrance.id, {
  returnScene: 'Overworld',
  returnPosition: playerPosition,
});
```

入口配置和触发判定不需要重写。

当前五个入口按照现有手绘标注图和转绘地图进行第一轮近似放置，主要用于验证操作闭环，并非最终测绘坐标。下一轮应在 Creator 预览中逐一行走核对，再微调：

| ID | 暂定名称 | 用途 |
|---|---|---|

### 在 Creator 中手动校准

层级结构：

```text
Canvas
└─ MapCalibration
   ├─ MapBackground
   ├─ Entrances
   │  ├─ Entrance-location-1
   │  ├─ Entrance-location-4
   │  ├─ Entrance-location-2
   │  ├─ Entrance-location-2-5
   │  └─ Entrance-location-3
   └─ PlayerStart
```

操作方法：

1. 在层级管理器选择 `MapCalibration`，把鼠标移到场景编辑器后按 `F`，让整张地图居中显示。
2. 展开 `Entrances`，选择要调整的 `Entrance-location-*` 父节点。
3. 按 `W` 切换移动工具，拖动彩色圆环；也可以在右侧属性检查器的 `Position` 中直接填写精确的 `X / Y`。
4. 调整出生位置时，拖动 `PlayerStart`。
5. 按 `Ctrl+S` 保存场景，再运行预览。运行时会优先读取这些保存后的节点坐标。

注意：

- 移动 `Entrance-location-*`，不要只移动它下面的 `Title`。
- 缩放 `Entrance-location-*` 会同时改变运行时圆环和自动进入范围；脚本会抵消父节点缩放，让所有 `Title` 保持统一显示大小。
- 不要移动 `MapCalibration` 或 `MapBackground`，否则底图参照系会改变。
- 彩色圆环的半径就是自动进入范围；当前半径仍在 `OverworldConfig.ts` 中设置。
- 如果删除 `MapCalibration`，脚本会在编辑模式重新按默认配置生成一套校准节点。

## 8. 操作与验收

电脑预览：

- `WASD` 或方向键移动；
- 也可用鼠标拖动左下摇杆；
- 进入彩色圆环应自动出现地点占位层；
- 点击占位层的返回按钮继续行走。

手机或微信小游戏预览：

- 单指拖动左下摇杆；
- 松手后摇杆回中且角色停止；
- 横竖比变化时摇杆和标题仍贴合屏幕安全区域；
- 地图边缘不能越界；
- 同一入口不能连续重复触发。
